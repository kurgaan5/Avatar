# Подготовка своего аватара

## Локальный профиль

- `portrait.png` и `combined_data.json.gz` создаёт `scripts/prepare_portrait.py` из одного источника. Они содержат лицо и его производные и хранятся локально в `profiles/`. Для видео можно выбрать нужный момент через `--start` и длительность нейтрального фрагмента через `--seconds`.
- `background.png` — необязательный квадратный фон. Для подбора костюма используйте портрет в нужной одежде или подготовьте новый портрет со сведёнными слоями. Внешний край маски стоит проверить возле волос, шеи и плеч.
- `gestures.npz` — необязательный банк движения. Чтобы извлечь его из 30–40 секунд сидячих поворотов, выполните `scripts/build_gestures.py input/motion.mp4 profiles/my-avatar`. Контракт описан в [архитектуре](architecture.md). Без него работает контроллер спокойных движений.
- `owner.npy` — необязательный локальный профиль CAM++. Чтобы создать его, выполните `scripts/setup_models.py speaker`, затем `scripts/enroll_speaker.py profiles/my-avatar input/voice.wav`. Возьмите 10–20 секунд разборчивой речи. После перезапуска появится переключатель фильтра. Этот файл управляет только допуском анимации рта.

## Вывод в Zoom

1. Для прямого вывода запустите портрет с `--direct-camera`. Выберите **OBS Virtual Camera** в Zoom. У виртуального устройства должен быть один производитель кадров. Если камера занята, освободите её перед стартом.
2. Для вывода через сцену уберите `--direct-camera`, добавьте в OBS браузерный источник `http://127.0.0.1:8776/feed` размером 720×720 и поместите его на сцену 1280×720. Запустите виртуальную камеру в OBS.
3. В панели браузера выберите физический микрофон и включите передачу в **CABLE Input**. В Zoom выберите микрофон **CABLE Output**. Колонки или наушники Windows и Zoom остаются обычным устройством воспроизведения.
4. Начальные буферы — 360 мс видео и 280 мс VB-CABLE. Запишите короткую проверку у второго участника. Сравните начало фраз, смыкание губ на «п», «б», «м» и синхронизацию. Фактические задержки зависят от устройств и нагрузки.
5. Для диагностики откройте `/api/health`. Проверьте `ready`, версии файлов и счётчики `head_late`, `render_late`, `coefficient_late`, `stream_resets`. Смотрите изменения за весь тест. Остановка и повторный запуск браузера не заменяют перезапуск сервера после смены профиля.

## Голос и ответы

Запишите короткий образец в тихой комнате с ровным расстоянием до микрофона. Подайте весь фрагмент длиной 8–10 секунд, с концом на паузе. Для передачи интонации добавьте `--transcript input/voice.txt` к `avatar_voice.py` и укажите точный текст именно этого фрагмента. Пробуйте новый текст с вопросами, числами и короткими фразами, чтобы оценить произношение и тембр.

Установите [Whisper.cpp](https://github.com/ggml-org/whisper.cpp/releases) и [llama.cpp](https://github.com/ggml-org/llama.cpp/releases) и добавьте их бинарники в PATH. Скачайте один GGUF Qwen3.5 из [источников в списке моделей](models.md), положите его в `.runtime/models/chat/` и подставьте имя файла. Для небольшого GPU начните с 4B. Qwen3.5 9B используется при достаточном запасе памяти после запуска TTS.

~~~powershell
.venv\Scripts\python.exe scripts/setup_models.py dialogue
llama-server --model .runtime/models/chat/Qwen3.5-9B-Q4_K_M.gguf --alias avatar-local --host 127.0.0.1 --port 18083 --ctx-size 4096 --jinja --n-gpu-layers 99
~~~

При запущенном сервере:

~~~powershell
.venv\Scripts\python.exe avatar_dialogue.py input/question.wav --reference input/voice.wav --persona examples/demo/persona.txt --output output/reply.wav
~~~

Для демонстрации без записи своего голоса можно создать образец установленным русским голосом Windows. Запустите `scripts/demo_speech.ps1` в Windows PowerShell 5.1 с установленным русским голосом для System.Speech. Этот WAV подходит для отладки, а качество клонирования проверяют на собственной записи.

Режим отдельного участника требует приложения [Zoom Meeting SDK](https://developers.zoom.us/docs/meeting-sdk/get-credentials/) и разрешений для целевой встречи. Этот репозиторий запускает локальный разговорный пример и вывод через виртуальную камеру. Подключение ответа к живому рендеру и отправка аудио и видео самим SDK описаны в [архитектуре](architecture.md).
